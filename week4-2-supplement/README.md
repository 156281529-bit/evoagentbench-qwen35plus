## 流程到底用上了什么经验？

固定旧代码和已注册的两个 Java 节点，每题给同一流程发送三次请求。第一组只给样例结果，第二组加入一条答对的新输入，第三组加入一条由独立算法验算、旧程序答错的新输入。这样可以排除“只要多给一个输入就会改变路由”的解释。

| 题目 | 仅公开样例 | 加一条通过的输入 | 加一条失败的输入 |
|---|---|---|---|
| abc382_g · 砖块距离 | 转人工 | 转人工 | 可进入修订 |
| arc186_d · 树序列计数 | 转人工 | 转人工 | 可进入修订 |

六次请求均由本机 RSI-Flow 的 `/api/engine/flow` 实际执行，节点顺序为 `WEEK4_DIAGNOSE → WEEK4_ROUTE`。输入和逐次调用号见 [native.pairs 记录](results.json)。本实验测的是进入修订前的路由。修复算法由 AI 参考题解实现，不能用这些回执推算实际节省的人时或宣称修复代码由节点自动生成。

## 两条能手算的反例

| 题号 | 完整输入（斜线表示换行） | 期望 | 旧程序 | 修订后 | 为什么 |
|---|---|---:|---:|---:|---|
| abc382_g | `1 / 2 -1 0 0 0` | 1 | 2 | 1 | 左边的竖砖与右边的横砖共用一段边，一步即达。旧程序把横砖与竖砖的条带编号之差也计作距离。 |
| arc186_d | `3 / 1 2 2` | 1 | 2 | 1 | 长度三只有两种树序列，分别为 `(1,1,0)` 和 `(2,0,0)`，只有前者不超过输入。旧程序在终点多计了一次。 |

**可复用的经验**是给“样例全过、正式失败”的轨迹补一个小规模精确求解器。先按题意生成期望值，再和旧程序比对，将短反例的输入、期望值、实际输出与候选哈希一同保存。改变题型时只替换生成器和求期望值的方法。本次几何题按单位方格恢复砖块邻接关系后做广度优先搜索，树题按定义枚举有序子树、排序后直接计数。经验适用于能构造独立参照的题目。缺少这种参照时，沿用原流程的人工分支。

合计 **3,156 条构造输入**。其中少量输入可与旧经验或公开数据重合，单表计数单位是输入。第二、三行超出第一行的近邻范围，避免只修正一个示例。完整输入生成规则和两个参照算法都在[复现实验脚本](experiment.py)。

砖块题的修订沿用公开题解中的对称性和周期性，将远距离问题化为有限个近邻情形，再在小图中计算精确距离。每次查询只做常数次算术运算并查表，避免对题面允许的巨大坐标展开网格。[修订代码](abc382_g.py) · [砖块题面](https://atcoder.jp/contests/abc382/tasks/abc382_g?lang=en) · [官方题解](https://atcoder.jp/contests/abc382/editorial/11488?lang=en) · [树序列题面](https://atcoder.jp/contests/arc186/tasks/arc186_d?lang=en)

**与原数据交叉验证。** 在按 SHA-256 校验的原批次上，本机独立进程精确复测得到砖块题旧代码公开 1/1 组、隐藏 0/1 组，修订后公开 1/1 组、隐藏 1/1 组。该题是原来的第十一道保留题。当前环境无权访问 Docker 命名管道，补充修订尚无原 Linux 容器判分回执。原十题的两道浮点输出分歧仍保留原判。

## 如何验证真的减少了人工介入？

本次两道选定题在诊断阶段的转人工数从 **2/2 降至 0/2**。这是路由事件计数。下一轮可在查看结果前登记 10 道新失败题，对同一批旧代码、同一判题器和同一次修订预算，分别运行原流程与加反例流程。逐题记录运行编号、转人工原因、人工实际介入次数、耗时、最终判分和未结案状态。两种流程都将 10/10 题处理至终态，另外单报正式修复率，防止用“已转人工”冒充“已修复”。若要求 100% 正式修复，则另设 10/10 正式通过门槛，达到门槛后再比较人工次数。

建议预先设定目标为“在正式修复率不下降时，每十题人工实际介入次数比同批对照至少降低 30%”。对照为零时只报次数差。新增输入的设计与独立参照的开发耗时另计，便于判断这项投入在哪些题型值得复用。

## 复现与分工

如已备妥 v2 的 Docker 镜像及 LiveCodeBench 检出，可单独运行以下命令，得到保留题的 Linux 判分。脚本校验镜像 ID 和代码库提交号。

```shell
python -B week4-2-supplement/verify_linux.py --lcb PATH_TO_LIVECODEBENCH --dataset recovery-source.json --out supplemental-linux.json
```
